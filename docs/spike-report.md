# M0 技术验证报告（第一轮）

> **日期**：2026-09-28 · **环境**：Windows，Chrome 153，已登录知乎 · **工具**：[M0 探针](../spike/m0-probe/) 0.1.0
> 对应[项目计划](./plan.md)中 M0 的检查清单。本文只包含汇总后的结论和数字；原始报告含有一处用户标识（见[第 4 节](#4-探针自身的问题)），不提交到仓库。

## 1. 结论一览

| # | 检查项 | 结论 | 说明 |
|---|---|---|---|
| 1 | 首屏数据与接口结构 | ✅ 基本完成 | 首页、回答页、用户主页的首屏数据，49 个接口的结构都已拿到；问题页、专栏文章、评论区还没覆盖 |
| 2 | 拦截并改写接口响应 | ✅ 可行，有一个坑 | 拦截覆盖率 100%，删减数据后页面正常；但**整页被删空时，知乎会不停地请求下一页** |
| 3 | 首屏：预隐藏 / 启动前改写 | ✅ 可行 | 每次都在知乎前端启动前拿到首屏数据；原样写回不影响页面；预隐藏样式生效且无闪烁。"删掉回答数据"还没在回答页上测 |
| 4 | 从内容元素找到数据 | ✅ 可行 | `data-zop`、React 属性、链接三种方式基本 100% 找到 id，且都能在数据中找到；**热榜页结构不同**，需要单独适配 |
| 5 | 单页应用路由 | ✅ 可靠 | 8 次跳转全部被 Navigation API 和 history 补丁立即发现，没有只靠轮询才发现的情况 |
| 6 | 用户脚本环境 | ✅ 全部通过 | 独立环境互相隔离；同步通信中位数约 0 ms；可以往已打开页面的已有环境里注入新代码（热重载的前提） |
| 7 | 知乎自带暗色 | ⚠️ 部分可用 | 切换 `<html data-theme>` 后正文区变暗，**顶栏不变** |
| 8 | Edge / Firefox | ❌ 未测试 | |

总体判断：计划里的技术路线成立，可以进入 M1。需要调整的地方见[第 3 节](#3-对计划和插件-api-的影响)，没覆盖到的项目见[第 5 节](#5-补测清单)。

## 2. 详细结果

### 2.1 首屏数据（`js-initialData`）

| 页面 | 大小 | 实体数量 | 读到时机 |
|---|---|---|---|
| 首页推荐 | 18 KB | 只有 `users: 1`（当前用户） | 页面解析中（`loading`），启动后 13–46 ms |
| 回答页 | 26–28 KB | `answers: 1`、`questions: 1`、`users: 1` | 同上，19–90 ms |
| 用户主页 | 21 KB | — | 同上，118 ms |

- 读到首屏数据的 9 次加载，每次都在知乎前端启动**之前**，一次就解析成功；在它之前只有 1 个外部脚本。
- **首页的首屏内容不在首屏数据里**：推荐内容是前端启动后用接口（`/api/v3/feed/topstory/recommend?desktop&limit`，6 条）加载的，约 1.7 秒后才出现在页面上。所以首页的过滤可以全部在接口层完成。
- 回答页是服务端渲染的，首屏数据里带着这条回答。
- 顶层字段：`initialState`、`subAppName`、`spanName`、`canaryConfig`；`initialState.entities` 下有 answers、articles、questions、users、pins、zvideos、comments 等 22 类实体。
- 有 1 次回答页加载既没有首屏数据，也没有任何接口请求，原因不明，补测时留意。

### 2.2 接口

一共见到 49 种接口。和插件相关的主要是：

| 接口 | 用在哪 | 条目类型（`data[].type`） | 要点 |
|---|---|---|---|
| `/api/v3/feed/topstory/recommend` | 首页推荐 | `feed`（420 条） | `target.type` 为 answer / article；`target.content` 里就有**正文 HTML**，还有摘要、赞同数、评论数、创建与更新时间、作者（含 `url_token`）、问题标题 |
| `/api/v3/moments` | 关注 | `feed`、`feed_advert`、`feed_group` | 广告是 `feed_advert` 条目；`feed_group` 里嵌套 `list[]`；动作见 `verb`（赞同、回答、提问、发想法） |
| `/api/v4/questions/:id/feeds` | 问题页 / 回答页的回答列表 | `question_feed_card` | **广告不在列表里**，而是响应顶层的 `ad_info`（带 `position`）；分页字段含 `need_force_login` |
| `/api/v3/feed/topstory/hot-lists/total` | 热榜 | `hot_list_feed` | 卡片式结构：`title_area`、`excerpt_area`、`metrics_area`、`link`，不是内容实体 |
| `/api/v4/search_v3` | 搜索 | `search_result`、`zvideo` | `object.type` 为 answer / article / question / zvideo；付费内容有 `paid_info.type = paid_column_content` |

- 上面这些内容接口的请求都带有 `x-zse-93`、`x-zse-96` 签名头（部分还有 `x-zst-81`）。这印证了"只旁听、不自己请求"的原则：自己发请求就得伪造签名。
- 推荐流的 70 个响应、420 条内容里没有见到广告（条目类型全是 `feed`）。

### 2.3 拦截与改写

- **覆盖率**：10 次页面加载，钩子拦到 552 次接口请求，浏览器资源计时记录 551 次，没有漏掉的接口。
- 10 次里有 3 次，`window.fetch` 在我们之后又被别的代码包了一层（可能是知乎的监控脚本，也可能是其他扩展），拦截不受影响。这说明拦截必须在 `document_start` 最早安装。
- **去掉一半条目**：10 个推荐流响应从 6 条删到 3 条，页面正常，没有报错。
- **去掉全部条目**：16 个响应被删空，每次知乎前端都在 1.1–1.6 秒后请求下一页，20 秒内连续请求了 16 次，页面上始终没有新内容。从数据上分不清是自动触发还是滚动触发，但结论相同：**整页被删空会造成"看不到内容、请求不停"**，这在风控上有风险。
- 拦截期间出过 1 次 `Failed to fetch`（读取响应体时请求已中断），不影响页面。

### 2.4 首屏实验

- **原样写回**首屏数据：在前端启动前完成，页面正常（人工确认）。
- **删掉一个回答的数据**：只在首页上试了，而首页的首屏数据里本来就没有回答，所以这项还没有结论。
- **预隐藏**（首页）：隐藏样式生效，24 个元素分 2 批处理，最慢一批 0.8 ms，没有触发超时放行，人工观察无闪烁。由于首页内容来自接口，预隐藏只对服务端渲染的页面（如回答页）才有意义。

### 2.5 从内容元素找到数据

对每个 `.ContentItem` 用几种方式找内容 id：

| 页面 | 内容元素 | `data-zop` | 链接 | React 属性 | 任一方式 | 各方式一致 | 在数据中找到 |
|---|---|---|---|---|---|---|---|
| 首页推荐 | 42 | 42 | 42 | 42 | 42 | 42 | 42 |
| 关注 | 11 | 9 | 9 | 9 | 9 | 9 | 9 |
| 搜索 | 60 | 45 | 56 | 56 | 56 | 56 | 56 |
| 用户主页 | 7 | 7 | 7 | 7 | 7 | 7 | 7 |
| 回答页 | 3 | 3 | 3 | 3 | 3 | 2 | 3 |
| 热榜 | 0 | — | — | — | — | — | — |

- `data-zop`（字段 `authorName`、`itemId`、`title`、`type`）覆盖回答和文章；搜索页的想法等卡片没有它，靠链接或 React 属性补上。
- React 属性（`data`、`answer`、`article`、`pin`、`content`、`item` 等）在所有内容元素上都有，但**只有页面主环境（MAIN world）能读到**。
- microdata 很丰富（`dateCreated`、`dateModified`、`upvoteCount`、`commentCount`、`zhihu:question` 等），适合取日期和数量，但探针 0.1.0 的写法取到的多是作者或问题的地址，id 命中率很低（0.1.1 已改进）。
- 找到的 id 100% 能在首屏数据或接口数据中对上，说明"数据层 + 元素识别"的方案可行。
- 关注页 2 个、搜索页 4 个元素没找到 id；回答页有 1 个元素各方式给出的 id 不一致。0.1.1 会记录这些情况的细节。
- 带 `css-xxxxxx` 哈希类名的元素占 25–34%，印证了"禁止依赖哈希类名"。
- **热榜页没有 `.ContentItem`**，需要单独的锚点（0.1.1 会检查 `.HotItem`）。

### 2.6 路由

8 次页面切换（首页、关注、热榜、搜索之间，以及搜索词变化）：

- 每次都是 Navigation API 最先发现；
- `pushState` / `replaceState` 补丁也都在 0 ms 内发现；
- 轮询在 176–599 ms 后才发现，没有只靠轮询才发现的情况。

### 2.7 用户脚本环境（Chrome 153）

- `userScripts` 可用；用 `worldId` 配置并注册两个独立环境都成功。
- 两个环境都看不到页面的全局变量、扩展隔离环境的全局变量，也看不到对方。
- 与扩展隔离环境通过 DOM 事件同步通信：200 次全部同步完成，中位数约 0 ms，最慢 0.1 ms。
- 与后台的扩展消息往返：中位数 1.4 ms，p95 5.9 ms。
- `userScripts.execute()` 能向已打开页面里的已有环境执行代码，热重载可行。
- 事件里的对象数据跨环境可读（Chrome 153）。
- `customElements` 在扩展隔离环境和用户脚本环境里都不可用。

### 2.8 暗色

把 `<html data-theme>` 从 `light` 切到 `dark` 后，页面背景从 `rgb(244, 246, 249)` 变为 `rgb(0, 0, 0)`，文字变为白色，但**顶栏没有变暗**（人工观察）。

## 3. 对计划和插件 API 的影响

1. **"数据优先"得到验证**：内容都能在数据里找到，而且正文 HTML 就在推荐流数据里，阅读模式和字数统计可以直接用数据。
2. **首屏按页面类型区分**：首页的首屏内容来自接口，过滤可以在渲染前完成；回答页等服务端渲染的页面，才需要预隐藏或在启动前改写首屏数据。
3. **过滤不能让一页变空**：一页数据被全部过滤时，宿主要保留一个占位条目（例如"已过滤 6 条"），并在连续多页为空时停止自动加载、改成"继续加载"按钮。已写入插件 API 第 6 节。
4. **广告有多种来源**：关注流的 `feed_advert` 条目、问题页回答列表顶层的 `ad_info`；推荐流本次没见到。适配层要统一成 `kind: 'ad'`。问题页的广告不在回答列表里，插件 API 需要给它一个过滤入口（记入插件 API 待定问题）。
5. **热榜单独适配**：条目是 `hot_list_feed` 卡片，页面上没有 `.ContentItem`，在 `FeedItem` 里映射为问题卡片。
6. **锚点优先级调整**：
   - 首选 `data-zop`；
   - 其次是 React 属性，由页面主环境里的一个小助手读取并给元素打上 `data-zb-id` 标记；
   - 再其次是链接；
   - microdata 只用来取日期和数量，不作 id 来源。
7. **付费内容标记**：搜索结果里有 `paid_info`；推荐流等其他接口的对应字段待查。
8. **主题**：复用知乎的 `data-theme` 暗色样式能覆盖大部分页面，但顶栏要单独补样式，或者找到知乎原生的切换方式（补测 `?theme=dark`）。
9. **挂载点**：两个环境都没有 `customElements`，挂载点用普通元素加 Shadow DOM（与计划一致）。
10. **路由检测**：Navigation API 加 history 补丁即可，轮询只作兜底。
11. **跨环境通信**：Chrome 上对象数据可以直接跨环境传递，但为兼容 Firefox，仍然统一传 JSON 字符串。

## 4. 探针自身的问题

原始报告里有一个**用户标识**（打开过的那个用户主页地址里的那段），出现在 4 处：

- 3 个接口地址里，形如 `/api/v3/moments/<标识>/activities` 和 `/api/v4/profile/<标识>/infinity`；
- 用户主页首屏数据结构里的一个键（`people.profileStatus`）。

原因是 0.1.0 只替换了 `/people/`、`/org/`、`/members/` 后面的那段，并且只折叠了有两个以上键的映射。

0.1.1 已修复：
- 页面地址和数据里出现过的用户标识（`url_token`）会被记下，并从地址、结构、错误信息里一律抹掉；
- 增加了 `/moments/<标识>/…`、`/profile/<标识>/…` 等形式，以及"含数字的连字符串"的识别；
- 只有一个键的映射也会被折叠。

冒烟测试加入了这几种情况：0.1.0 在这些检查上失败，0.1.1 全部通过。

## 5. 补测清单

用探针 0.1.1 补测以下内容，大约 10 分钟：

1. 在地址栏直接打开一个问题页（`/question/数字`），往下滚动加载更多回答；展开一条回答的评论，翻一页评论。
2. 打开一篇专栏文章（`zhuanlan.zhihu.com/p/…`），展开评论。
3. 在一个回答页上，把"首屏数据改写"设为"删掉一个回答的数据"，刷新，看页面是否正常，然后改回关闭。
4. 打开热榜。
5. 打开 `https://www.zhihu.com/?theme=dark`，看顶栏是否也变暗，结果写在"人工观察"的备注里。
6. （可选）在 Edge 上安装一遍，看"允许用户脚本"开关在哪里、弹窗是否显示可用。
