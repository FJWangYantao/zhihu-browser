# 页面样本（fixtures）

知乎改版是这个项目最大的风险（见[项目计划](./plan.md)第 10 节）。页面样本是适配层的回归测试：
从真实的知乎页面采集一份脱敏的样本，放进仓库；之后每次改适配层，或者知乎改版之后重新采集，
`pnpm test` 都会让适配层把每一份样本重新识别一遍，指出哪里对不上。

## 采集

1. 安装并打开扩展（构建方法见 [README](../README.md#开发)），**保持默认设置**：不要开"隐藏右侧栏"，不要开屏蔽，
   这样样本里有完整的页面和右侧栏的位置。
2. 打开要采集的知乎页面，等内容加载完（想采评论就先展开评论区）。
3. 按 Ctrl+K（macOS 上是 ⌘K）打开命令面板，运行"采集页面样本"。
4. 面板里显示的就是样本。**先看一遍**，再点"下载"（或"复制"）。扩展不会上传任何东西。

需要采集的页面（M1 验收范围）：首页、问题页、回答页、专栏文章（带评论区）、搜索页，再加上热榜和用户主页。
每类最好采两份：窗口宽度大约 1400 和 800（知乎在窄窗口下换布局），以及浅色和暗色各一份。

如果命令面板里提示"采集失败：样本没有通过脱敏检查"，说明脱敏代码有漏洞，样本已经被拦下、没有输出。
请把提示里的文字发给开发者（提示只描述哪一类内容没脱敏，不含内容本身）。

## 样本里有什么、没有什么

脱敏用白名单：不是复制页面再删东西，而是按白名单重新生成一份 HTML，没列入白名单的东西一律不进入样本。
生成之后，还有一个独立的检查（`auditSnapshot`）逐项核对结果，不通过就不输出。

| 保留 | 不保留 |
|---|---|
| 标签名、类名（包括 `css-xxxxxx`）、短的英文 `id` | 页面上所有文字：换成同样长度的占位符（汉字→"文"、字母→"x"、数字→"0"），只保留"收起""阅读全文"这类固定的界面文案 |
| `itemprop`、`itemscope`、`role`、`data-theme` | 图片地址、图片说明、样式、输入框的值、无障碍文字、其他 `data-*` 属性 |
| 内容 id、评论 id：换成编号（同一个 id 在整份样本里编号一致，页面元素和实体的对应关系不变） | 真实的内容 id、用户主页标识、作者名、标题 |
| 链接的路径形状（`/question/编号/answer/编号`），日期（只到天）、点赞数、评论数 | 链接的查询参数；外站链接；`javascript:` 链接 |
| 一部分元素的位置和大小（`data-rect`）：内容元素往上每一层和它们的兄弟，两栏布局的测试要用 | 扩展自己插入的界面和标记（`data-zb-*`） |
| 页面上实体仓库里有的内容和评论的键（编号后），用来核对"页面元素能不能对应到数据" | 接口响应的内容 |

一份样本最多保留 12 块内容、24 条评论，多出来的连同外层卡片一起去掉。

## 提交样本

样本放在 `packages/adapter-zhihu/test/pages/`，文件名 `<页面类型>-<说明>.json`，例如 `home-wide-dark.json`。
提交前：

1. 打开文件看一遍，确认没有不该出现的东西（自己的用户名、私密内容）。
2. 看 `expect` 一节：这是采集时适配层的观察结果，`pnpm test` 会据此检查。
   如果适配层当时判断错了（比如内容数量不对），请手工改成正确的值，让测试暴露问题。
   - `contents`：内容元素的数量
   - `comments`：能对应到数据的评论元素的数量（不写就不检查）
   - `columns`：`true` 表示按位置能找到两栏布局的右侧栏（不写就不检查）
3. 在 `note` 里写一句备注：页面类型、窗口宽度、明暗、采集日期。
4. 运行 `pnpm test`。

## 测试检查什么

`test/pages.test.ts` 对每一份样本检查：

- **脱敏**：`auditSnapshot` 重新核对一遍（防止有人手工编辑时带进敏感信息）；
- **锚点**：`health.ts` 里为这类页面声明的锚点都命中了期望的数量；
- **内容识别**：每个内容元素都能认出是哪块内容，并且这块内容在实体仓库里；
- **评论、布局**：按 `expect` 检查评论数量、右侧栏的位置识别；
- **适配层整体**：把样本装进页面，跑一遍真正的适配层：每块内容都被识别，健康检查没有停用任何功能，没有内容被误藏。

失败信息会写出是哪个元素（标签名和类名）、哪个锚点，可以直接据此修 `dom/anchors.ts` 或 `health.ts`。

## 合成样本

`test/pages/synthetic-*.json` 是**合成的**：由 `test/synthetic.ts` 按 [M0 报告](./spike-report.md)记录的结构手工搭建，
再经过真正的采集工具生成，不是真实页面。它们让整条流水线（采集 → 脱敏 → 装载 → 检查）在没有真实样本时也能被测试。
真实样本足够之后，可以逐步删掉对应的合成样本。

合成样本由 `test/synthetic.test.ts` 检查"已提交的文件和现在生成的一致"；改了采集工具或合成页面之后，
运行 `UPDATE_FIXTURES=1 pnpm test` 重新生成。

## 用样本补充健康检查的锚点声明

`health.ts` 的 `ANCHOR_SPECS` 故意声明得很保守：误报会停用正常的功能。有了各类页面的真实样本之后：

1. 在样本里确认某个类名在这类页面上稳定存在（多份不同窗口宽度、明暗的样本都有）；
2. 加进 `ANCHOR_SPECS`，写明这类页面上应命中多少个；
3. `pnpm test` 会用所有样本验证这条声明，样本里对不上的会立刻暴露；
4. 对于"合法的零"（搜索无结果、没有折叠内容、想法没有标题），不要声明。
